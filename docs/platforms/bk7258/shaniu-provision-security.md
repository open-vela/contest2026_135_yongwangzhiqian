# provision-v1 认领与配网安全决策

状态：双端 TLS、认领事务、Android 输入/扫描入口及板端整包存储模块已实现；
只读恢复协议及 UI 已实现，板端按键/广播与网络运行期接线、实板验收尚未完成。
执行顺序及退出门仍由 [主计划](shaniu-master-plan.md) 的 F4 管理。

Android `provision/ProvisionTls.kt` 已实现确切证书 pin、日期及用途校验和 TLS 1.2
客户端 engine 工厂。主机临时 P-256 证书测试验证正确 pin 可握手并发送测试字节，
错误 pin 在握手失败且无应用字节，过期/尚未生效证书被拒绝；Android 构建通过。
测试尚未覆盖 Android SSLEngine ↔ mbedTLS/GATT，不能替代手机或实板互通证据。

`ProvisionTlsChannel` 已驱动 SSLEngine 的握手任务、密文输入和应用数据收发，
使用有界缓冲，握手完成前拒绝发送明文应用消息；密文错误、输出队列拒绝及超限输入
关闭当前通道。单个通道只属于一次连接，关闭后不能重用，持有者负责 GATT 断连、
连接代际过滤和握手超时。回调只能同步复制/入队，不能在蓝牙回调或 UI 线程执行 TLS。
主机双 engine 测试覆盖 20 字节分片握手、4096 字节上行及下行往返、密文篡改、
握手前写入、输出背压和输入上限。Android 平台队列及板端 TLS 实现见下文，
双端各自的主机测试不能代替 Android ↔ AIDK 互通验收。

`ProvisionGattSession` 已接 TLS 通道与有界收发队列：按协商的 ATT MTU 减 3 拆分，
每次只允许一个 write-with-response 在途，成功回执后才释放队列容量；回调同时校验
连接 generation 和 write token。断连、写失败、超限输入及超时关闭通道并清空缓冲。
握手上限 30 秒、单次写回执 5 秒、总连接 120 秒，持有者必须持续调用 tick，
时间源回退也关闭连接。主机双 TLS 会话测试验证 MTU 23→185、4096 字节传输、
旧代际/重复回执过滤及超时/队列失败；Android 测试和 APK 构建通过。
该类要求所有方法在同一 worker 串行调用。AndroidProvisionGatt 已接平台回调：
服务发现→MTU 请求→CCC 通知订阅→TLS，跨线程事件队列限制为 128 项，
失败和取消统一关闭平台连接；仅处理本连接及目标特征的回调。CONNECT 权限已声明，
运行时授权和设备选择已由 `ProvisionActivity` 接入。平台回调代码已通过编译，
现有 TLS/队列主机回归通过；尚无手机回调顺序、权限拒绝、蓝牙断连或实板互通证据。

产品 GATT UUID 独立于 N13 测试服务：服务为
`81e70001-9b31-4c48-9c62-e6da4b392531`，手机写入特征为
`81e70002-9b31-4c48-9c62-e6da4b392531`（WRITE with response），板端通知特征为
`81e70003-9b31-4c48-9c62-e6da4b392531`（NOTIFY，标准 CCC）。
特征值只承载 TLS 密文字节流，不承载明文 Wi-Fi 配置。

板端前置核查确认当前 GATT 注册会替换单一属性表，产品启动须选择完整产品表，
不能再叠加注册测试表。目标配置已启用 mbedTLS SSL server 和 ECDHE-ECDSA。
通知 API 的无返回值问题已整理为 `nuttx/patches/bluetooth/0001`：
新增 `bt_gatt_notify_checked`，返回交给 L2CAP 的 PDU 数或无发送时的负错误；
修复 16 位通知句柄截断、每 peer CCC 判定和断开连接引用释放，保留原 void API
及零长度通知。固定上游基线补丁应用、实际函数 host 编译测试和隔离 AIDK CP/AP
构建通过。返回值不是 ATT 确认或手机接收证明；服务发送窗口、认领和实板验收仍未完成。

板端 `bk7258_provision_gatt.[ch]` 已提供完整 GAP+产品表、4096 字节密文接收环、
CCC 代际、窗口关闭清理及定向发送接口。诊断 AP 在 Host 启动完成后的产品
start 回调注册完整表，不自动广播或打开窗口。
每次 TLS 发送临时持有原连接引用，并使用补丁新增的 `bt_gatt_notify_peer`；
原连接断开时不会改发新订阅者。产品 worker 必须在 Host 空闲时注册、
在本地确认和凭据就绪后开窗口，并在窗口结束时停止广播、断开实际连接。
现阶段窗口 worker/广播操作尚未接入，不构成可用配网服务。
host 测试覆盖未开窗口拒绝、4096 字节溢出、环回读写、旧代际、关闭清理和连接引用；
实际 AIDK AP 对象及 CP/AP 镜像构建通过。

板端 `bk7258_provision_tls.[ch]` 复用工作区 mbedTLS 3.4.0，提供绑定单次 GATT
generation 的 TLS 1.2 ECDHE-ECDSA/AES-128-GCM 服务端 BIO。身份通过借用的证书/
私钥句柄供应，启动验证密钥匹配，不从路径自动读取或产生设备身份；客户端认证仍需
后续 TLS 内 possession proof，服务端不要求手机持有设备客户端证书。
通知每次最多 20 字节、间隔至少 10 ms；L2CAP 拒绝时有界重试，已入队片段不重发。
握手 30 秒、单次应用发送 5 秒、整个连接 120 秒；时间回退、旧代际及终止错误清理
SSL/随机数上下文和自有明文缓冲。发送挂起时保留同一 buffer，不交错调用 TLS read。
这些 API 要求同一产品 worker 串行驱动；`bk7258_provision_pair` 已接 TLS 和认领
状态机，但产品 worker 的身份供应、按键及网络/存储回调仍未接入。

`tests/host/bk7258/test_provision_tls.py` 使用实际 mbedTLS 双端与临时 P-256 证书，
验证 20 字节分片、拥塞恢复、双向 1024 字节、无重复记录、篡改拒绝、握手超时、
代际切换和时间回退清理；并非模拟 TLS 返回值。AIDK CP/AP 构建同时通过。
主机的默认 mbedTLS 配置、GATT 队列模型与目标配置分别验证，仍欠手机与板端互通、
真实 HCI 流控和功耗/资源测量，10 ms 间隔也不是实测吞吐结论。

当前 Host 属性写回调长度为 uint8_t，Android 发送再限制为每次最多 244 字节，
即使协商到 MTU 517 也不发送超过此上限的数据。板端通知暂时固定不超过 20 字节。

## 问题与复用边界

当前 `chips/bk7258/ap/bk7258_ble_gatt.c` 是单连接 ECHO/BURST 测试服务，
固定 20 字节帧与 CRC 只用于测试，不提供凭据保密或设备认领。
当前官方 `nuttx/wireless/bluetooth/bt_smp.c` 的配对处理清除 MITM/SC/KEYPRESS 位，
不能据此承诺认证配对。产品不复用测试 UUID 或向该服务添加 Wi-Fi 密码命令。

继续复用 BK7258 HCI 传输、NuttX Host/ATT/GATT、既有 Wi-Fi 接口及非秘密偏好 KVDB。
产品服务、事务及认领策略属于 `app/bk7258`；不改变 SDK 控制器所有权。
既有 `bk7258_voice_tls.c` 是 WSS 客户端，只参考其 mbedTLS 使用与清理方式，
不能直接作为 BLE TLS 服务端或修改其既有服务器证书验证。

## 选定的认证通道

GATT 仅传输 TLS 密文字节流，使用标准 TLS 实现，不另造加密算法。
板端采用现有 mbedTLS，Android 采用 SSLEngine；TLS 1.2 及以上，禁止降级到明文。
GATT 适配必须处理 ATT MTU、分片、有界队列、背压、连接代际和中断，
不得把 ATT 回调变成阻塞 TLS/文件/Wi-Fi 工作线程。

认领所需 bootstrap 由设备供应流程生成，包含协议版本、稳定设备 ID、
设备证书 SHA-256 指纹及每设备独立的 256 位随机 possession secret。
通过设备所有者持有的二维码供应；不能从广播、MAC 地址、序列号或固定常量派生。
二维码是秘密，不放在常驻屏幕、广播、普通通知、日志或公开仓库。
当前尚无这条供应流程，不能把手动串口配置标成已完成 App 认领。

Android 在发送任何秘密前校验二维码指定的确切设备证书指纹、证书有效期及
TLS 握手中的私钥持有证明。不使用 trust-all、不接受临时未知证书，也不把发现名称
或 BLE 地址当身份。证书轮换要求新的授权 bootstrap，旧指纹不能自动放行。
设备 TLS 服务端建立连接不代表手机已认领；必须在加密通道内验证 possession secret。
secret 比较使用现有密码库常量时间比较，失败只返回统一认证错误。

设备本地按键打开有界认领窗口；只允许一个待认领事务，并要求本地确认后才能配置。
远程包不能模拟按键确认。窗口结束、失败次数达到上限、断线或取消都丢弃临时认证态，
旧连接与旧事务不能继续写入。已认领设备默认关闭首次认领入口；重新认领和解绑要求
设备本地恢复操作，不能仅凭仍保存着的首次二维码覆盖当前所有者。

## 配置事务和存储

当前实现采用 SPV1 固定 32 字节头（类型、递增序号、事务 ID、长度），以及
SCB1 完整候选包。板端 `bk7258_provision_claim` 只接受可信本地确认调用；网络
包没有确认按键操作。`bk7258_provision_store` 将修订号、事务 ID 和配置 SHA-256
随完整文件同步后原子替换，目标限定私有 LittleFS；散列只检查完整性，不宣称加密。
AP 文件调用必须由独立持久 worker 承担，不能让 RPMsgFS 阻塞 ATT/TLS 超时处理；
`bk7258_provision_storage` 已接产品启动，独立保存候选与提交结果，缺失私有目录
不会自动创建或格式化。阻塞 fsync、重复请求、断线后提交及重启回执读回已有主机验证。
不确定发布禁止通过同一挂载上的读回或停止/重启 worker 清除，需实际重启后核对。

Android `ProvisionBindingStore` 在 APPLY 发送前保存设备/事务 ID，保存失败阻止
发送，断线后不删除未知回执；板端返回 COMMITTED 后，绑定设备 ID 与删除匹配回执
在同一次 SharedPreferences commit 中完成。该索引不含 Wi-Fi/认领秘密。写入失败时
UI 只得到 UNCONFIRMED，进程重启后继续核对，不会把板端回执误报成本机已绑定。
已有索引时禁止新提交；`ProvisionActivity` 的“核对上次提交结果”
发送原事务 AUTH，再经本地确认发送 QUERY=5（seq1、空负载），不上传配置。板端独立
只读窗口调用非阻塞 receipt 回调，1 返回 COMMITTED=6，0 返回 NOT_COMMITTED=9，
暂未完成继续等待，其他错误返回 UNCERTAIN=8。已选中其他事务不能证明旧事务未提交。
恢复认证失败不清除原回执；查询明确成功/不存在且本机原子写入成功才发布最终状态。
旧版 App 的非原子设备镜像不能升级为权威绑定，只能引导重新核对或导入控制凭据。
产品 owner/GATT 接线已有源码和主机测试；界面提供凭据/CA 导入和扫描，仍需设备供应
流程及真实手机/板端联调，不能用模拟器测试替代。

TLS 内消息必须带版本、随机事务 ID、递增消息序号及有界长度。
认证前只允许握手/认证消息；认证且本地确认后才接收 SSID、密码和 Gateway 配置。
Wi-Fi、Gateway TLS/设备身份验证分别返回结果；只有二者成功且持久提交成功后才返回
COMMITTED。网络成功不能替代磁盘提交成功。提交失败保留旧的已确认配置，
重启按最后完整提交恢复；禁止将半套证书、地址和 Wi-Fi 密码组合使用。

MiMo API key 继续仅在 Gateway，不下发板端或 Android。Gateway 地址及证书信任约束
随事务校验，不能将任意 URL 当作已认证端点。板端长期设备私钥优先在设备生成，
由注册流程签发公钥对应凭据；首次 bootstrap 不能自动签发任意设备或用户权限。

普通 KVDB 偏好接口不作为秘密存储接口直接暴露。Android 使用现有 Keystore 保护
本地秘密；板端软件存储需限制访问和日志，并与配置事务统一管理。当前不宣称具备
安全元件、Flash 提取防护或物理攻击保护；固件签名本身不能证明数据保密。
实现前需验证 TLS 服务端证书/随机数供应、秘密存储权限及旧配置恢复路径。

## 必须留下的验收证据

- 主机双端 TLS：正确 pin/secret 成功；错误 pin、错误 secret、过期证书失败，
  验证失败前不发送 Wi-Fi 密码；不会因错误改成明文。
- ATT MTU 23 及更大 MTU 下分片、队列溢出、取消、断线、旧连接回调与 TLS 清理。
- 本地确认前不能提交；认领窗口、失败上限、旧二维码及旧事务重放被拒绝。
- Wi-Fi 错误密码、Gateway 验证失败、磁盘提交失败和提交阶段掉电后恢复旧配置。
- Android 与 AIDK 20 次发现/认领/配网/取消/重连/解绑；检查广播、抓包及日志中
  没有明文凭据，检查凭据不进入测试报告或构建产物。

这些是待完成的退出门，不是当前已经通过的测试。

## Bootstrap 输入格式

Android `ProvisionBootstrap` 接受最多 1024 字符的严格 JSON 对象，恰好四个字符串字段：

| 字段 | 格式 |
| --- | --- |
| protocol | `provision-bootstrap-v1` |
| device_id | 1–128 字符，字母或数字开头，后续仅字母、数字、点、下划线、冒号、短横线 |
| certificate_sha256 | 设备叶证书 DER 的 SHA-256，64 位小写十六进制；不是 SPKI pin |
| possession_secret | 32 随机字节的标准规范 Base64，含 padding，共 44 字符 |

重复/未知字段、尾随 JSON、错误类型、非规范编码全部拒绝，解析错误不携带输入或原异常。
对象的字符串表示固定脱敏。持有者在取消/完成时调用 close 清除拥有的已解码数组，
秘密使用回调的临时数组在正常返回或异常时均清除；扫码/输入组件另行清除自己的缓冲。
Gson/JVM 不可变字符串副本无法通过该模型保证擦除。

解析成功仅表示结构合法，不表示随机数质量、设备归属或认领成功。输入 UI、供应端随机
凭据生成、TLS 内 possession 验证及设备本地确认仍需实现；模型不主动持久化或发送秘密。
严格解析与关闭/异常清理测试及 Android APK 构建已通过；当前执行证据由主计划管理。
