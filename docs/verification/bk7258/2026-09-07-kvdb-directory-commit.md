# KVDB 目录同步与提交结果不确定性验证（2026-09-07）

延续真实 UnQLite 主机恢复测试，新增目录同步和日志删除故障注入。
补丁仍维护于团队 `external/patches/unqlite/0001-propagate-commit-sync-errors.patch`，
未修改官方 checkout、SDK 或板级配置。

## 本轮修复与测试

启用目录同步时，unixSync 不再忽略目录同步错误；commit phase2 检查事务日志删除
结果，失败时标记需要回滚。新增两种故障在修复前均复现 commit 错报成功；修复后
返回 -EIO，恢复旧值。前一轮日志/数据库同步、DIRECT、强制退出恢复场景同时通过。

`make -C tests/host/bk7258 run-kvdb-unqlite` 退出 0。

另外在确认日志 unlink 成功后，注入最后的目录同步 EIO，验证：

1. commit 返回 -EIO，没有报告保存成功。
2. 当前句柄因回滚无法完成而拒绝进一步读写。
3. 关闭并重新打开后，两键均为新值；提交失败并不总表示旧值仍在。
4. 测试显式读回协调状态后恢复夹具旧值，后续事务可继续。

失败注入按实际 unlink 事件定位；仅按目录同步次数选择阶段不可靠，因为同一提交
可能同步数据库和日志各自的目录。测试同时覆盖 fsync/fdatasync。

## 交付边界

这是 Linux 主机故障与恢复证据，不等于实板掉电验收。目标配置仍未开启 KVDB，
文件锁、目录/介质同步和资源预算需继续闭合。上层保存失败后必须读回协调实际状态；
不得在没有证据时显示“已恢复旧设置”。128MB/SDIO 已合并基线不因此重新排查。
