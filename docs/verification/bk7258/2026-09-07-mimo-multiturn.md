# MiMo 有界多轮对话验证（2026-09-07）

本轮验证 Gateway 连接内短期上下文；不覆盖实板 PTT、MIC/DAC、Android 或长期记忆。
沿用生产 `python -m shaniu_gateway` 服务与 companion-v1 协议。

## 实现范围

- `MiMoProvider.new_conversation()` 为每个连接创建独立历史；替换旧共享回复回调入口。
- 最多最近 4 个完整 user/assistant 问答，总计不超过 8192 字符，超限删除最旧完整问答。
- 生成完成先待提交，成功发送 TTS_END 后提交；生成失败、取消、超时不提交。
  设备报告最近一轮播放错误时撤回该轮。发送完成不等于实际播放完成。
- 断连清空，历史仅在内存中存在；固定 system policy 与用户内容保持独立角色。

## 真实服务验证

使用赛事提供的 MiMo 接口，内置音色生成两条非私人测试语音；WAV 头核实为
24000 Hz、mono、S16，转为 16000 Hz 后通过本机 WSS 上传生产 Gateway。
第一轮提供一个普通偏好信息，第二轮询问该信息；不保存原始文本或音频。

|---|---|---|
| 请求携带的历史问答数 | 0 | 1 |
| 首音频延迟 | 2470 ms | 1937 ms |
| 整轮耗时（含下行节奏） | 5696 ms | 3100 ms |

| 正常结束 | 是 | 是 |

第二轮回答包含第一轮的测试信息。聚合结果：completed=2，protocol_errors=0。
只有两个样本，不代表准确率、P50/P95、长稳或真实声学效果。

测试 TLS 证书/私钥临时生成并清理；供应商密钥不写入日志或仓库。
音频与文本仅在内存处理，测试完成后服务器关闭。
流式裸 PCM 与实测 WAV 采样率一致仍沿用当前接入假设，实际播放速度和听感待实板确认。
